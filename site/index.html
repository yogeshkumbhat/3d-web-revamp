01 The problem

Most 3D sites fail the same way.

The scene is built first and everything else is retrofitted. What ships is a dark slab with a loading spinner.

  • FAIL · 01

    A beautiful scene that is the only thing on the page.

  • FAIL · 02

    A 6 MB bundle before the first frame renders.

  • FAIL · 03

    A blank page for crawlers, screen readers and anyone without WebGL.

  • FAIL · 04

    Content lost in the rewrite — pages, schema and conversion paths nobody made room for.

This skill exists to prevent all four. It gives Claude a method, hard numbers, and working code for the parts that are easy to get wrong and invisible when you do.

03 The method

Seven phases. Code starts at the fourth.

Most of what makes a 3D site good is decided before anyone writes new THREE.Scene().

00

Phase 00 · Revamp only

Audit before anything.

The most common failure in a revamp is dropping pages, copy, schema markup or conversion paths because the new design “didn’t have a place for them.” So Claude takes an inventory first — and says plainly when 3D is the wrong answer.

# pages, copy, headings, meta, palette, fonts, analytics hooks
python scripts/audit_site.py https://yoursite.com

“Your site is slow and the copy is weak, and 3D fixes neither.”

Sometimes the honest verdict — SKILL.md

01

Phase 01

Pick one category. Don’t blend.

3D does a different job in each. Blending them is why generic “3D websites” feel like a demo reel. If you’re unsure, one question decides it: what does a visitor need to believe before they convert?

CategoryWhat the 3D is for
CommerceLet the buyer inspect and configure the actual thing they’ll receive.
BrandOne restrained moment that signals craft, then gets out of the way.
NarrativeCarry a story as the visitor scrolls.
PortfolioThe site is the work sample.

02

Phase 02

Art direction before code.

Generic 3D looks generic because it starts with a scene and decides how it should feel afterwards. Claude writes the direction down first — emotion, materials, light, camera, and how type sits against the 3D — and asks what genuinely needs a GPU.

Precision and cold restraint. Five anodised plates on near-black, one soft cool key from high left, a thin cyan rim. The camera is choreographed; the cursor only nudges it. Type lives in the quiet left of the frame, never over the stack.

03

Phase 03

Build it bottom up.

Claude starts from a verified starter, not an empty file, and builds in an order that makes a failed WebGL context, a crawler or a slow phone get a complete site instead of a blank div. Scroll — the stack builds in the same order.

  1. Static HTML, all content

    Fully working with zero JavaScript. Everything meaningful is real markup.

  2. A poster in the 3D container

    Rendered from the scene itself. It is the LCP element, and the fallback.

  3. The scene, mounted lazily

    Only after first paint, only with WebGL, only above the floor tier, only when visible.

  4. Interaction and motion

    Damped, small-range, with a reason to move. Never free orbit on a brand hero.

  5. Polish — last, if there’s budget

    Grain, rim light, bloom. The first things cut when a budget fails.

04

Phase 04

Budgets are pass or fail.

Not aspirations. If an effect breaks a budget, the effect goes — bloom and god rays first, and almost nobody notices.

  • 2.5sLCP on a mid-tier Android over 4G. The canvas is never the LCP element.
  • 1.5MBBrand hero payload, gzipped. 2.5 MB configurator, 4 MB narrative.
  • 60/30 fpsDesktop, and the mobile floor. Drop a quality tier, not frames.
  • ≤50callsDraw calls on mobile; ≤100 on desktop. No main-thread task over 50 ms.

05

Phase 05 · Non-negotiable

Take the 3D away. The page stands.

Four audiences never see your scene: crawlers, reduced-motion users, browsers without WebGL, and low-end devices. They share one static path, built once.

  • ContentEvery word in the DOM. Crawlers and screen readers never depend on the canvas.
  • Motionprefers-reduced-motion gets stillness — not the same journey, slower.
  • PosterShown when WebGL is missing or the context is lost.
  • KeyboardEvery interaction the 3D offers is also a real button.
  • Canvasaria-hidden when decorative; described properly when not.

06

Phase 06

Measure. Then say it passed.

A checklist filled in from guesses transfers confidence without transferring evidence. The budget checker drives the real page — LCP and which element it was, draw calls counted at the GL context, frame time, drift, and every fallback path — and exits non-zero on failure, so it can gate a deploy.

node scripts/check_budget.js http://localhost:8080 --mobile --gpu
  LCP                 0.64s             PASS
  LCP element         p.lede            PASS
  Frame time p95      16.7 ms           PASS
  Draw calls p95      19                PASS
  Long tasks > 50ms   0                 PASS
  No WebGL            poster + content  PASS
  RESULT: PASS — all measured budgets met

Real output for this page: 4× CPU throttle, throttled 4G, a 390px phone viewport. The first run failed on two 55 ms tasks during scene setup; they were split up until it passed.

06 What’s inside

Scripts that measure. A starter that works.

The skill tells Claude which reference to read at each phase, and gives it tools that report real numbers rather than impressions.

  • assets/starter/

    A verified reference build: mount gate, device tiering with a live frame-time probe, context-loss recovery, poster crossfade, full disposal. Run it live.

  • scripts/audit_site.py

    Page inventory, copy, headings, meta, palette, fonts and analytics hooks from a live site.

  • scripts/optimize_assets.sh

    glTF → Draco or meshopt → KTX2, with a budget verdict. A 1.03 MB fixture ships at 682 KB gzipped.

  • scripts/check_budget.js

    LCP, CLS, draw calls, triangles, frame time, drift and all three fallback paths. Exits non-zero on failure.

  • scripts/capture_poster.js

    Renders the poster from the live scene in AVIF, WebP and JPEG, so it never drifts from the scene. Every still on this page came from it.

  • scripts/optimize_video.sh

    A video hero encode ladder: H.264, VP9, poster and a reduced-motion still, budget-checked.

  • scripts/verify_starter.mjs

    Drives the starter headlessly through visible, reduced-motion and background-tab states. It gates every deploy of this site.
